## Architecture (`feature-first`)


```text
lib/src/
├── features/
│   ├── auth/             # Common Parent/Nanny flow
│   ├── onboarding/       # Common Parent/Nanny flow
│   ├── splash/           # Common Parent/Nanny flow
│   └── roles/
│       ├── parent/<feature>/
│       └── nanny/<feature>/
├── shared/               # cross-feature widgets & utils only
├── routing/
├── services/
└── theme/
```

**Rules**

- Each feature is self-contained — no imports from another feature's internals.
- Shared code lives only under `lib/src/shared/`.
- Common screens and flows used by both roles live directly under `features/`.
- Parent-only and Nanny-only features live under their respective
  `features/roles/<role>/` directory.
- Models, repository contracts/implementations, controllers, screens, and
  feature widgets stay in separate files and layers as defined in
  [`architecture.md`](architecture.md).

## State management (getx)




- Controllers extend `GetxController`; reactive fields use `.obs` with `Obx()`.
- Register controllers via bindings / route setup — avoid inline `Get.put()` inside widgets.
- `GetMaterialApp` is configured when navigation uses GetX — do not add a second material app wrapper.
- Controllers own business actions, validation decisions, async state, and
  repository/use-case calls. Screens only render and forward user intent.



---

## Navigation



- Pages and bindings are registered via `AppRouter.getPages` in `lib/src/routing/app_router.dart`.
- Use GetX navigation APIs consistent with the existing router setup.
- Do not mix in a second routing package alongside GetX pages.


---

## Backend (custom)




- HTTP/Dio client is configured in `lib/src/config/app_config.dart`.
- API calls belong in `lib/src/services/` (e.g. auth service) using the shared client.
- Base URL comes from environment / config — see **SETUP.md**.

For console setup (keys, native files, env), follow **[SETUP.md](SETUP.md)** — do not duplicate platform steps here.

---

## Networking

- Use the shared `Dio` instance from `lib/src/config/app_config.dart` — never `Dio()` inside a widget or screen.
- Define backend paths in `lib/src/config/api_endpoints.dart`; services reference
  `ApiEndpoints` instead of inline endpoint strings.
- Extend or use existing services under `lib/src/services/` for HTTP calls.
- Map transport errors to `Failure` / `FutureEither` results via `runTask()` — do not leak raw `DioException` to UI.



---

## Services & shared conventions

- Services are singletons with `ClassName.instance`, returning `FutureEither<T>` via `runTask()`.
- Never pass `BuildContext` into services — use `rootContext` from the global navigator helper when UI is required.
- Logging: `AppLogger`; user feedback: `showGlobalToast()`; dialogs: `showAppDialog()` / `context.showAppDialog()`.
- Initialize `AppLogger` once in `main()` and never log credentials, tokens, or
  personal childcare/family data.
- Primary import barrel: `package:alurei/src/imports/imports.dart`.
- File names: `snake_case.dart`; classes: `PascalCase`; private members: `_camelCase`.
- Prefer `const` constructors where possible; avoid `dynamic` without justification.
- Use `IconsaxPlusLinear`, `IconsaxPlusBold`, or another appropriate Iconsax
  variant for standard interface icons. Do not use Flutter's default `Icons.*`.
  A supplied design-specific SVG may be used when it is registered in
  `AppAssets` (for example, the main navigation artwork).
- No empty `catch` blocks — log, map to failure, or rethrow.
- Do not add packages that duplicate existing stack choices (routing, state, backend).

### Dart / Flutter anti-patterns

- No business logic in widget `build()` methods.
- No direct backend or network calls from presentation widgets.
- Default to `StatelessWidget`; use `HookWidget` for disposable local UI state.
  Use `StatefulWidget` only for a lifecycle or mixin requirement hooks cannot
  cleanly represent.
- Screen files contain route-level composition only. Put screen/feature-specific
  components under `presentation/widgets/`.
- Extracted widget classes cannot be Dart-private across files; keep them
  feature-internal by not exporting them from public barrels.
- A widget repeated within one role belongs in that role's `shared/widgets/`; a
  role-neutral widget repeated across roles/features belongs in
  `lib/src/shared/widgets/`.
- Do not mix GetX routing with GoRouter/AutoRoute in the same app.

## How to add a new feature

### Figma image assets

- When a Figma design contains raster images, retrieve them through the Figma
  MCP asset URLs and store them under `assets/images/`; never leave expiring
  Figma URLs in Dart code.
- Give downloaded files semantic `snake_case` names, register their paths in
  `AppAssets`, and use the local asset path from widgets.

1. Classify it as common, Parent-only, or Nanny-only.
2. Create it under `features/<feature>/`, `features/roles/parent/<feature>/`, or
   `features/roles/nanny/<feature>/`.
3. Separate `data` models/repository implementations, `domain` entities/contracts,
   and `presentation` controllers/screens/widgets.
4. Register controllers through bindings and routes through `AppRouter.getPages`.
5. Add every visible string to English, Arabic, Filipino, and Sinhala translation
   files.
6. Regenerate typed keys and use `LangKey.<section>.<key>.tr()`; never type raw
   localization paths in widgets.
7. Use centralized theme colors/tokens and promote only genuinely reusable UI to
   the appropriate shared directory.
8. If an API is unavailable, define a repository/data-source contract and use a
   dummy implementation backed only by `lib/src/shared/dummy_data/` fixtures.

flutter pub get

### Code generation

This stack uses `build_runner` (Hive, etc.):

```bash
dart run build_runner build --delete-conflicting-outputs
```

Re-run after changing generated routes, MobX stores, Hive adapters, or Firebase-related generated code.

### Localization

Supported locales are English (`en`), Arabic (`ar`), Filipino (`fil`), and
Sinhala (`si`). Every translation key must exist in all four JSON files, and
Arabic UI must be verified in RTL.

After editing `assets/translations/*.json`:

```bash
dart run tool/generate_lang_keys.dart
```

The generator validates matching keys across all four locales and writes
`lib/src/shared/localization/generated/lang_key.g.dart`. Use typed keys such as
`LangKey.auth.name` and never edit the generated file by hand. Generated getters
apply `.tr()` internally; callers must not append it.

## Hard limits

- Do not disable `flutter_lints` rules without an explanatory comment.
- Do not call backend or networking code directly from widgets.
- Do not commit `.env` files containing production secrets.
- Do not introduce a second state-management or routing library.
- Do not put business logic, repository calls, service calls, or dependency
  registration inside screens/widgets.
- Do not create feature-local color classes or hardcode hex colors in UI. Add
  every raw value to `lib/src/theme/app_colors.dart`, then expose theme-dependent
  meanings through `ColorScheme` or `AppColorsExtension` for both themes.
- Inter is the application font. Use `context.textTheme` for standard roles or
  `GlobalTextStyles` for justified custom styles; do not instantiate
  `GoogleFonts` or set another font family inside features/widgets.
- Main backgrounds and text hierarchy must come from the brightness-selected
  `context.colors` / `context.appColors` palette documented in `DESIGN.md`; never
  use light palette constants directly in feature UI.
- Do not ship a translation key unless it exists in all four supported locales.
- Do not put dummy values directly in UI/controllers or let production bindings
  select dummy data. Central fixtures live only in `lib/src/shared/dummy_data/`.
- Figma MCP output is a visual specification, not finished application code.
  Connect interactions, controllers, navigation, localization, loading/empty/
  error states, and repository-backed dummy data before considering a screen
  functional.
- For platform setup and API keys, use **[SETUP.md](SETUP.md)**.
- For UI tokens and spacing, use **[DESIGN.md](DESIGN.md)**.
